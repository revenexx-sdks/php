# MarketingConsentsEvidence Service


```http request
GET https://api.revenexx.com/v1/marketing-consents/consent-events
```

** The proof, newest last when ordered by `at`. Filter by `subscription_id`, `contact_id`, `kind`, `source`. Read only — no address answers PUT or DELETE. **

### Parameters

| Field Name | Type | Description | Default |
| --- | --- | --- | --- |
| id | string | Filter to rows whose `id` is exactly this value. The row's own id, generated by the database. A caller never sends one; it reads one back and puts it in the path of later calls. |  |
| subscription_id | string | Filter to rows whose `subscription_id` is exactly this value. The subscription this fact belongs to. |  |
| contact_id | string | Filter to rows whose `contact_id` is exactly this value. The `customers` contact holding the address. Null until one exists — a sign-up creates one at lifecycle stage `subscriber` — and after an erasure. |  |
| subscription_type_id | string | Filter to rows whose `subscription_type_id` is exactly this value. The subscription type this row belongs to. |  |
| channel | string | Filter to rows whose `channel` is exactly this value. How the address is reached: email, sms or whatsapp. |  |
| address_hash | string | Filter to rows whose `address_hash` is exactly this value. SHA-256 of the normalised address, hex. Every lookup goes through it, and it is the only part of the address an erasure keeps. |  |
| kind | string | Filter to rows whose `kind` is exactly this value. What happened: requested, confirmation_sent, confirmed, withdrawn, lapsed, imported, basis_changed or erased. |  |
| source | string | Filter to rows whose `source` is exactly this value. Where it came from: form, storefront (a shop sign-up box), import, admin, unsubscribe_header (RFC 8058 one-click), preference_centre, order, complaint (a spam report) — and, on events only, system (the lapse job). |  |
| source_ref | string | Filter to rows whose `source_ref` is exactly this value. What exactly it came from: a form id, an order id, a message id, an import id. |  |
| legal_basis | string | Filter to rows whose `legal_basis` is exactly this value. Why a send is allowed: consent_doi (double opt-in), consent_single (imported single opt-in, weaker proof), existing_customer (§7 (3) UWG) or contract (never a basis for advertising). |  |
| consent_text_id | string | Filter to rows whose `consent_text_id` is exactly this value. The published consent text — wording and version — the person agreed to. Null for the existing-customer basis and for imports, which saw no wording. |  |
| campaign_ref | string | Filter to rows whose `campaign_ref` is exactly this value. The campaign the sign-up came from, as the caller named it (a campaigns id). Attribution only. |  |
| page_url | string | Filter to rows whose `page_url` is exactly this value. The page the sign-up or confirmation happened on, when the caller sent it. |  |
| ip | string | Filter to rows whose `ip` is exactly this value. The IP address of the person at a sign-up or confirmation, when the caller sent it. Shortened after `ip_retention_days`. |  |
| user_agent | string | Filter to rows whose `user_agent` is exactly this value. The browser of the person at a sign-up or confirmation, when the caller sent it (at most 512 characters). |  |
| ip_truncated_at | string | Filter to rows whose `ip_truncated_at` is exactly this value. When the IP address was shortened by the retention job. |  |
| at | string | Filter to rows whose `at` is exactly this value. When it happened. Server time — the authoritative time of the proof. |  |
| created_at | string | Filter to rows whose `created_at` is exactly this value. When the row was created. Server-set. |  |
| limit | integer | Page size (default 50, max 200). A larger value is clamped. |  |
| offset | integer | Row offset (default 0). |  |
| order | string | Sort by one column: 'column', 'column.asc' or 'column.desc'. |  |

```http request
POST https://api.revenexx.com/v1/marketing-consents/contacts/{contact_id}/erase
```

** An erasure request (Art. 17 GDPR). Withdraws every open subscription first (so the sequencer suppresses), then removes address, contact, IP, browser and page from every row and keeps type, basis, times and the address hash — so eligibility answers `erased` and an import cannot bring the address back. Publishes `consents.erased` per address. **

```http request
POST https://api.revenexx.com/v1/marketing-consents/imports
```

** Up to 1000 rows per call. Every accepted row becomes a confirmed subscription on the basis the import claims — consent_single or existing_customer, never double opt-in — with an `imported` proof pointing at the import. Unknown addresses become `customers` contacts first. An address that withdrew or was erased is refused: an import never overrules an objection. **

### Parameters

| Field Name | Type | Description | Default |
| --- | --- | --- | --- |
| channel | string | Defaults to email. |  |
| file_ref | string | Which file the rows came from, in the uploader's words. |  |
| legal_basis | string | The basis every imported row gets: consent_single or existing_customer — never double opt-in, the import did not see a click. |  |
| proof_note | string | Where the consent of these addresses is documented: system, period, form. Required, because an import without it is a claim without proof. |  |
| rows | array | Up to 1000 rows. |  |
| subscription_type | string | The code of the type. |  |

```http request
POST https://api.revenexx.com/v1/marketing-consents/sweep/run
```

** Until the platform delivers other apps' events (PE-748), this reads them from their owners: the sequencer's newest unsubscribe and complaint suppressions (48 h) become withdrawals — rows this app wrote itself are skipped; orders placed in the last three hours open the existing-customer basis; subscriptions without a contact are linked to the customers contact of their address. Idempotent; the hourly `sweep-events` schedule runs it. **
